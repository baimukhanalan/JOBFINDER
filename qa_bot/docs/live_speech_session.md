# Одна разрешённая тестовая попытка SHL / TP

`qa_bot.live_session` управляет отдельным окном Chrome и одной заранее выбранной
тестовой попыткой. Он получает приглашение только для точного имени профиля:
через HTTP JobFinder с паролем из окружения либо из уже раскрытого письма в
браузере, указанном через `--source-browser`. Список кандидатов не обходится,
отметка «ассессмент пройден» в JobFinder не меняется. Подписанная ссылка остаётся
в памяти процесса и не записывается в журнал.

Для текущего адаптера реализованы четыре раздела:

- **A — Read and Speak:** точный видимый текст, один локальный TTS, затем MP3/WAV
  из постоянного банка. Чужая секция не распознаётся как предложение для чтения.
- **B — Listen and Repeat:** в микрофон подаётся исходный аудиобуфер вопроса.
  Выбирается фактически запущенный звук; предварительная загрузка следующего
  вопроса не заменяет текущий. Для ответа STT, LLM и TTS не нужны.
- **C — Listening Comprehension:** сохраняются все реально проигранные реплики
  HTML-аудиоплеера в исходном порядке. Локальный STT обрабатывает их по очереди,
  решатель получает весь разговор. Перед выбором проверяются номер, текст и
  варианты ответа. Предложения решателя сохраняются как `candidate`, без
  выдуманного утверждения человеком или официальной проверки правильности.
- **D — Free Speech:** подготовка начинается, когда появляется точная тема.
  Готовый ответ ищется до вызова решателя; новый ответ синтезируется и сохраняется
  один раз. WAV проверяется по SHA-256 и длительности (15–42 секунды), затем
  запускается только при `Speak Now` для того же вопроса и темы.

Все речевые разделы используют один аудиопоток. Современный и старые callback
варианты `getUserMedia` получают один и тот же вход. Платформенный диктофон
наблюдается отдельно: сохраняется именно созданная им запись, её формат,
длительность и сила сигнала. Наличие файла в банке само по себе не означает,
что сайт принял ответ.

В режиме ожидания вход содержит очень тихий шум (амплитуда 0,001), поскольку
платформа ошибочно считает длительный цифровой ноль зависшим устройством и
обращается к отсутствующему старому диктофону. При `Speak Now` этот шум отключается,
в том числе если ответ не подготовлен. Он ниже собственного порога проверки речи
и не засчитывается ботом как голос. Исходные MP3/WAV в банке остаются неизменными.

После окончания ответа бот дожидается разрешённой кнопки `SUBMIT ANSWER` и
отправляет запись. Это исключает длинную тишину в конце, которая запускала
проверку отсутствия голоса. Таймеры и проверки платформы не изменяются.
Переходы выполняются обычными кликами по уникальным доступным элементам,
включая кнопки в закрытом shadow DOM. Неоднозначные и отключённые кнопки
не нажимаются.

## Запуск

Нужны Python-окружение проекта, Chrome, установленный Natively с локальной
моделью, macOS `say`/`afconvert` и авторизованный Codex CLI для новых смысловых
ответов. ElevenLabs в этом варианте не вызывается. Все сервисы слушают только
localhost и проверяют точный Origin и общий случайный токен.

Перед запуском задаются `QA_LOCAL_BRIDGE_TOKEN`, `QA_CAPTURE_TOKEN` (тот же
локальный токен), `JOBFINDER_LOGIN`, `JOBFINDER_PASSWORD`. Значения не включаются
в репозиторий. Команды выполняются из `qa_bot` в отдельных терминалах:

```sh
PYTHONPATH=src .venv/bin/python -m qa_bot.speech_bridges \
  --origin https://amcatglobal.aspiringminds.com \
  --profile authorized-profile --test authorized-test --output runs/authorized-test \
  --counter-selector 'button.currentQue' --suspension-selector '[id^="ngdialog"]' \
  --repeat-section 'Section B: Listen and Repeat'

PYTHONPATH=src .venv/bin/python -m qa_bot.audio.capture_bridge \
  --origin https://amcatglobal.aspiringminds.com \
  --output runs/authorized-test/evidence --port 18772

PYTHONPATH=src .venv/bin/python -m qa_bot.live_session \
  --selected-profile 'EXACT AUTHORIZED PROFILE NAME' \
  --profile-id authorized-profile --test authorized-test \
  --output runs/authorized-test/evidence/owned \
  --prompt-dir runs/authorized-test/prompts --auto
```

`--auto` включает речевые ответы, выбор ответов по диалогу, возобновление
попытки и переходы после инструкций. Из уведомлений автоматически обрабатывается
только ранее проверенный необязывающий Candidate Data Protection Notice с точным
текстом checkbox. Новые экраны, CAPTCHA и договорные подтверждения требуют
отдельной обработки; режим не нажимает произвольные «согласен».

В stdin доступны JSON-команды `state`, `audio_evidence`, `screenshot`, `close`.
`close` закрывает только принадлежащее этому процессу окно теста.

## Материалы проверки

`states.jsonl` фиксирует переходы, `actions.jsonl` — отправку речи,
`choices.jsonl` — ответы и их происхождение, `topics.jsonl` — сохранённую речь,
`transcripts.jsonl` — расшифровки с SHA-256 оригиналов. MP3 и записи диктофона
находятся в игнорируемом Git каталоге `runs`. Текст вопросов, персональные данные
и токены не следует переносить в документацию или коммиты.

`tools/index_repeat_prompts.py` переносит явно перечисленные исходные MP3 из
manifest в точный речевой банк. STT даёт только текстовый индекс, аудио не
генерируется. Отчёт отдельно отмечает совпадение SHA-256 исходного и сохранённого
MP3. `speech_usage` означает подготовку/повтор, а не оценку платформы.

Успешное завершение отдельных разделов, завершение диагностического прохода
с исправлениями и чистый автономный проход с начала — разные результаты.
Готовность всего сценария подтверждается только последним и видимым конечным
состоянием платформы; оценка речи требует отдельного результата от платформы.

## Неречевые разделы

В текущем диагностическом проходе платформа также подтвердила завершение Typing
и Personality. Печать выполняется событиями клавиатуры с проверкой всех символов.
Личностный опросник сопоставляет видимые формулировку и все пять пунктов шкалы
с историческим корпусом. Рекомендации корпуса не являются официальным ключом
и не описывают личность реального пользователя.

Адаптер аналитики получает снимок текущего вопроса и исходные изображения,
которые видимая страница показывает как миниатюры. Загрузка изображения должна
завершиться до решения. Отправка разрешена только при неизменных номере, тексте,
вариантах и источниках изображений; выбор проверяется по состоянию настоящего
радиопереключателя внутри платформенного компонента. Расчёт дополнительно
проверяется локально; числовые варианты с единицами допустимы только при
одинаковых единицах во всём списке. Точные текстовые совпадения могут использовать
исторический корпус, но задания с рисунками решаются по их фактическому содержимому.

`--auto` также запускает аналитику, WriteX и Sales после появления проверенного
формата. WriteX сохраняет переносы строк исторического письма и отдельно
заполняет адрес, тему и тело. Sales связывает две разные строки с подписанными
элементами Best/Worst и проверяет оба выбранных переключателя.

Первый диагностический проход достиг конечного экрана платформы. Typing,
Personality (72/72), WriteX и Sales (20/20) завершились; аналитика истекла по
таймеру после 7 из 19 ответов во время отладки. Этот проход не является успешной
сквозной проверкой. В текущей версии явный тайм-аут записывается как отказ и
отключает автоматические переходы. Чистая проверка с начала остаётся обязательной.
