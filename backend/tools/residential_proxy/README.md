# Residential proxy — домашний IP как egress для сервера (turnkey)

Пускает автоматизацию сервера (co-pilot / заполнение форм) через **домашний интернет** машины
владельца, чтобы дойти до ATS, которые блокируют датацентр-IP (Teleperformance/iCIMS, Kelly/Akamai,
reCAPTCHA-Greenhouse). Maximus/Avature работает и с сервера — ему это не нужно.

## Владельцу (turnkey — открыл, скачал, запустил)
**Страница (публичная, без пароля):** `https://proxy.systeam.kz/` — одна ссылка, одинаковая для всех
машин. Авто-определяется ОС и две кнопки:
- **Скачать и подключить** → Windows `win.exe` (двойной клик, без терминала) · macOS `mac.command`.
  Запустил → ставит автозапуск при входе и уже работает в фоне (окно не нужно держать открытым).
  Несколько машин можно подключить одновременно — сервер ротирует их IP (слоты 8120–8129, до 10).
- **Отключить** → `win-off.bat` / `mac-off.command` — останавливает и убирает из автозапуска.

Статус — файл `~/.jobfinder-proxy/status.txt` (`«Подключено ✓»` пишется ТОЛЬКО когда сервер реально
поднял слот — ложного «подключено» на заблокированной сети быть не может). Капча на сайте → открыть
noVNC `https://jobs.systeam.kz/vnc/` и решить; форму заполняет бот.

## Как устроено
```
Машина: агент (Go, один бинарь) — chisel-туннель на сервер по HTTPS/WebSocket (443), НЕ по :22
        занимает первый свободный слот 127.0.0.1:8120..8129 (обратный SOCKS5, loopback)
nginx:  proxy.systeam.kz  /  -> публичная страница+бинари   /link -> chisel-сервер (127.0.0.1:8096, WSS)
Сервер: co-pilot берёт слот-прокси (socks5://127.0.0.1:812x) -> трафик уходит в интернет ЧЕРЕЗ машину
```
Транспорт — **443/WSS** (переживает сети, где закрыт исходящий SSH/:22 — из-за чего первый вариант на
:22 давал ложное «подключено»). `proxy_pool.next_proxy()` пробит весь диапазон, ротирует ВСЕ живые
слоты round-robin и предпочитает их над Bright Data; отключилась машина — её слот пропадает из пробы и
перестаёт использоваться; слотов ноль — откат на Bright Data. Playwright ходит через no-auth loopback
SOCKS5 напрямую. Автопереподключение — экспоненциальный backoff (потолок 60с), слоты перебираются по
кругу.

## Сборка / деплой (разработчику)
`bash build_and_deploy.sh` — кросс-компилит клиент (`client/`, вшивая chisel-креды через `-ldflags` из
`dist/chisel_auth`), генерит установщики + страницу и деплоит в **`/var/www/proxy-plain/`** (публичный
корень). Требует `go` на PATH и `dist/chisel_auth` (тот же `user:pass`, что в `/opt/jf-chisel/auth`).
Клиент один: `client/main.go` (+ `notify_*`) — режимы установка (по умолчанию) / `--run` / `--uninstall`.

Одноразовая серверная настройка (НЕ в скрипте):
- **systemd `jf-chisel`** (юзер `jfchisel`, nologin): `chisel server --reverse --keyfile /opt/jf-chisel/key
  --authfile /opt/jf-chisel/authfile --host 127.0.0.1 --port 8096`. `keyfile` даёт СТАБИЛЬНЫЙ fingerprint
  (пиннится в клиенте); `authfile` ограничивает креды **только** `^R:127\.0\.0\.1:812[0-9]$` (реверс —
  только в loopback-слоты, ничего публичного).
- nginx-vhost `proxy.systeam.kz` + `certbot --nginx -d proxy.systeam.kz`: `location = /link` → WSS на
  `127.0.0.1:8096`; `location /` → публичная страница+бинари. `00-default-drop` default_server (чужой
  хост → 444) оставлен на месте.

## Безопасность (см. глобальный CLAUDE.md, инцидент 2026-04-16)
- Серверный конец — **только loopback** (`chisel --host 127.0.0.1`, слоты `127.0.0.1:812x`), наружу
  порт НЕ открыт; снаружи достижим только nginx-путь `/link` (WSS) и публичная страница.
- `authfile` жёстко ограничивает креду **только реверс-биндами в 127.0.0.1:8120..8129** — попытка
  `R:0.0.0.0:<port>` отклоняется сервером (проверено live: `access ... denied`, порт не поднимается).
- Клиент **пинит fingerprint сервера** (`chiselFP` в `main.go`) поверх валидного Let's Encrypt TLS —
  MITM невозможен.
- **Принятый компромисс (решение владельца):** страница ПУБЛИЧНАЯ и креда вшита в публичный бинарь —
  кто знает домен, может скачать и поднять слот/стать exit-нодой. Допустимо: через туннель идёт только
  заполнение форм синтетическими персонами по HTTPS (низкая чувствительность), и креда ротируется одной
  командой. Больше слота в loopback-диапазоне утёкшая креда не даёт (см. `authfile`).
- **Ротация креды:** `printf 'jf:%s' "$(openssl rand -hex 12)" | sudo tee /opt/jf-chisel/auth`, тем же
  значением обновить единственный ключ в `/opt/jf-chisel/authfile` и `dist/chisel_auth`,
  `sudo systemctl restart jf-chisel`, `bash build_and_deploy.sh`. Старые бинари перестают подключаться.

## Файлы
- `client/` — Go-исходники (в git; chisel-креда НЕ в исходниках, вшивается `-ldflags` при сборке).
- `index.html` — лендинг (в git).
- `build_and_deploy.sh` — сборка+деплой (в git).
- `dist/` — gitignored: `chisel_auth`, бинари, установщики (секреты/артефакты). `client/key.pem` больше
  не используется (транспорт chisel, не SSH).
