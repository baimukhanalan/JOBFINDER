# OCR: текущие возможности и граница внедрения

## Поток

DOM → проверка пустых data-ocr-id → OCRProvider → проверка hash/координат/
confidence/согласованности → повторный QuestionExtractor → QuestionSpec
с ocr_evidence → RunState. Ошибка означает spec=None и review_required,
старый маршрут очищается. Никаких решений или ответов.

Если все помеченные поля заполнены DOM-текстом, OCR не вызывается.
Если хотя бы одно пусто, проверяются все помеченные поля, включая заполненные:
отличие распознанного полного текста от DOM останавливает обработку.
Автоматическое сравнение частичных строк/нечёткое совпадение не применяется.

## Реализованный локальный движок

LocalOCRProvider читает binary RasterImage из памяти. decode_pbm(bytes)
декодирует растровый P1 PBM. Нет поиска готового ответа по ID/имени файла.
Распознаются пиксели букв A–Z, цифр 0–9, пробела, точки и минуса шрифта
synthetic-5x7-v1. В профиле заданы 5x7 glyph, пустая шестая колонка,
целочисленный масштаб 1–8, до 256 символов на регион.

OCRRequest задаёт изображение и известную область/масштаб, но не ожидаемый текст.
OCRResult содержит image_hash, region, tokens с текстом, координатами
(x, y, width, height), confidence и provider.
Координаты относительно изображения, а не viewport/DOM.

Confidence локального движка — сходство пикселей с шаблоном, не вероятность
правильности. Для synthetic-5x7-v1 принимается только точное совпадение 1.0;
повреждённые/неоднозначные пиксели отклоняются. Пустой результат тоже отклоняется.
Другие движки используют OCRPolicy (по умолчанию 0.95), проверку каждого блока,
границ региона, принадлежности изображению и соответствия DOM.

В таблицах известная DOM-структура th/td сохраняется; OCR заполняет пустые
ячейки. В графиках читаются подписи и числа из явно заданных областей.
Восстановление произвольной таблицы из изображения, понимание высоты столбцов,
оси/легенды, произвольные шрифты, кириллица, поворот и PNG/JPEG не реализованы.

## Как заменить локальную реализацию

- OCRProvider.recognize(request, timeout) — единый интерфейс движка.
  Общие модели не требуют сетки 5x7; это ограничение только LocalOCRProvider.
- OCRInputSource.prepare(snapshot, timeout) — контракт будущего получения
  изображения: screenshot либо fixture. Сейчас requests явно передаёт вызывающий
  код; автоматического захвата/скачивания изображений нет.
- extract_with_ocr получает provider и requests через аргументы, не создаёт
  клиентов и не знает URL движка/credentials.
- observe_once принимает ocr_provider/ocr_requests; CLI пока оставлен DOM-only.
- Один предел времени на OCR-пакет, отмена, ограниченные размеры изображения и
  число регионов. В журнале только количество принятых регионов и ошибки,
  без текста, пикселей и URL query.

Для настоящего движка следующая реализация: источник PNG screenshot →
декодирование/нормализация → provider (локальный движок или отдельно разрешённый
сервис) → тот же validator. Сначала contract tests с fake-провайдером, затем
проверка на разрешённых изображениях. Перед передачей изображений внешнему
сервису нужно отдельное разрешение. Текущий OCR не отправляет их никуда.

## Страницы с токеном и проверка HTTPS

Browser Controller не ограничен localhost. Он принимает HTTP/HTTPS только
для явно перечисленных --allow-origin. Полная ссылка берётся из QA_PAGE_URL,
не из исходников или конфигурационного файла:

```powershell
$env:PYTHONPATH = (Resolve-Path src).Path
.\.venv\Scripts\python.exe -m qa_bot --observe --allow-origin https://amcatglobal.aspiringminds.com
```

До запуска QA_PAGE_URL должна быть настроена в защищённом окружении.
Не вставляйте credential в командную историю/README/Git. Если сайт требует
другие origins, их нельзя разрешать автоматически или через wildcard.
Открытие autologin URL может создать сессию на стороне платформы.

Тест test_ocr_https использует настоящий Chromium и HTTPS URL с синтетическим
query token, но HTTP-ответ перехвачен fixture: это проверка совместимости
пути и отсутствия утечки токена, не live-проверка AMCAT.
Реального QA_PAGE_URL в среде нет, но после уточнения пользователя ранее
переданная ссылка отдельно открыта во встроенном браузере: SHL показал
Candidate Online Assessment Data Protection Notice, checkbox ознакомления
и Continue. Подтверждение не отмечалось, Continue не нажималась; вкладка закрыта.
Это live-проверка доступа, не запуск Python OCR на реальном вопросе.
Live DOM AMCAT не поддержан автоматически: неизвестная разметка остаётся
unknown/review_required. Токен не добавлен в код, настройки или журнал бота.

## Проверки

Полный unittest suite включает OCR букв/чисел, отдельный PBM файл таблицы,
генерируемую растровую подпись графика, DOM-first, конфликт, повреждение,
неверные hash/координаты/полноту, timeout, замену провайдера и RunState.
Общий OCR-процент точности на реальных изображениях и coverage не измерялись.
